## 一、定位与范围

本模块为全系统提供"跨项目长期积累"能力,是产品「越用越好」核心卖点的底座。共 4 个代码文件 + 1 份种子数据 + 1 份共享契约:

| 产出 | 类型 | 职责 |
|------|------|------|
| `contracts.py` | 共享契约 | `TermEntry` / `TMEntry` 数据类,与开发计划 §3 一致 |
| `rag_terms.py` | 代码 | ChromaDB + bge-m3 语义检索,`search_rag` / `write_rag` |
| `tm_store.py` | 代码 | SQLite + RapidFuzz 模糊匹配,`search_tm` / `write_tm` |
| `user_prefs.py` | 代码 | 用户偏好读写,`load_prefs` / `save_prefs` |
| `seed_terms.json` | 数据 | ~200 条 ICT 种子术语 |

**技术分工(来自概念文档 §6.4)**:术语用 RAG(语义检索,跨语言无字符串相似度,必须语义);翻译记忆用传统 TM(ICT 文本模板化,字符串匹配精准且零成本);用户偏好用 SQLite。

## 三、数据契约(`contracts.py`)

与开发计划 §3「统一数据契约(D1 锁定)」完全一致:

```python
from dataclasses import dataclass, field

@dataclass
class TermEntry:
    term: str
    translation: str
    domain: str = ""
    confidence: str = "medium"      # "high" | "medium" | "low"
    action: str = "translate"       # "translate" | "notranslate"
    source: str = ""                # "RAG命中" | "Web搜索" | "LLM生成" | "用户确认" | "种子数据"

@dataclass
class TMEntry:
    source_seg: str
    target_seg: str
    quality_score: float = 0.0
    similarity: float = 0.0         # 仅 search_tm 返回时填充;write_tm 忽略
```

**契约归属建议**:`contracts.py` 放仓库根,由 A(翻译核心)/ C(知识库)共用。A 的译前/译中/译后 Sub-Agent 引用同一份定义,避免两边各写一份导致 D6 联调字段对不上。

## 四、接口定义(6 个函数)

```python
# ── rag_terms.py ──────────────────────────────────────────────
def search_rag(query: str, domain: str = "", user_id: str = "",
               top_k: int = 5) -> list[TermEntry]:
    """语义检索术语库。返回按相似度降序的 TermEntry 列表;
    低于命中阈值(RAG_MIN_SIMILARITY)时返回空列表——调用方据此判定"未命中,转 Web 搜索"。"""

def write_rag(entries: list[TermEntry], user_id: str = "") -> list[str]:
    """写入/更新术语。以 (user_id, term) 为稳定 id,重复写入自动覆盖(upsert)。返回 ids。"""

# ── tm_store.py ───────────────────────────────────────────────
def search_tm(source_seg: str, threshold: float = 0.85, top_k: int = 5,
              user_id: str = "") -> list[TMEntry]:
    """RapidFuzz 全文模糊匹配。命中行填充 similarity(0~1)。"""

def write_tm(entry: TMEntry, user_id: str = "") -> int:
    """写入一条翻译记忆。返回自增行 id;同 (user_id, source_seg) 重复时覆盖更新。"""

# ── user_prefs.py ─────────────────────────────────────────────
def load_prefs(user_id: str) -> dict[str, str]:
    """加载用户偏好,返回 {preference_type: value} 字典。"""

def save_prefs(user_id: str, prefs: dict[str, str]) -> None:
    """批量保存用户偏好(upsert)。"""
```

> 阈值常量全部集中在 `config.py`:`RAG_MIN_SIMILARITY = 0.70`(D10 用种子数据校准)、`TM_MIN_SIMILARITY = 0.85`(概念文档 §6.3 已定 85%)、`TM_QUALITY_THRESHOLD = 8.5`(概念文档 §6.3 质检评分门槛)。

## 五、存储设计

### 5.1 RAG 术语库(ChromaDB + bge-m3)

- **引擎**:`chromadb.PersistentClient(path="data/knowledge/chroma")`,collection 名 `terms`,建库时声明余弦空间 `metadata={"hnsw:space": "cosine"}`(bge-m3 官方建议 normalize + 余弦)。
- **Embedding**:`BAAI/bge-m3`,sentence-transformers 加载,`normalize_embeddings=True`,维度 1024,支持 100+ 语言。
- **集合结构**:

| 字段 | 存储位置 | 说明 |
|------|---------|------|
| `term` | documents | 被检索的原文术语(如 `container orchestration`) |
| `translation` | metadata | 译法(如 `容器编排`) |
| `domain` | metadata | ICT 子领域,检索时精确过滤消歧 |
| `confidence` | metadata | high / medium / low |
| `action` | metadata | translate / notranslate(裸 API 名、命令等) |
| `source` | metadata | RAG命中 / 种子数据 / 用户确认 等 |
| `user_id` | metadata | 个人化过滤(MVP 默认 `default`) |
| `timestamp` | metadata | 写入时间 |

- **稳定 id**:`md5(user_id + "::" + domain + "::" + term)`——id 含领域,同一术语在不同领域可各成一条(同词多译),重复导入按 (user, domain, term) 覆盖不堆积。
- **领域兜底**:检索带领域时,用 `$or` 同时匹配「指定领域」和「空领域(全局)」——没填领域的通用术语任何领域都能命中。
- **缩写别名索引**(`rag_aliases.db`,SQLite):导入时从括注提取别名(`Central Processing Unit (CPU)` → `CPU` / `central processing unit`),`search_rag` 先做确定性精确匹配再语义检索。解决 bge-m3 对"缩写↔全称"相似度不足过不了阈值的问题,见 §6.1。
- **中文译法别名键**(2026-08-10 新增):同一别名索引中,每条术语的中文译法也建成别名键(`数字签名` → `Digital Signature`),支持**中文源文文档**(产品确认支持)。动机:中文 query×英文 term 的跨语言语义相似度实测仅 0.58~0.78,过不了 0.70 阈值,确定性键是唯一可靠路径;中文译法→英文术语一对一无歧义,不需要消歧表。只取中文含义(`数据挖掘(Data Mining)` → 取 `数据挖掘`),防中英混合译法引入英文键去撞已有英文术语。由 `update_aliases` 自动维护(改版后 `write_rag` / `--rebuild` 自动带出)。

### 5.2 翻译记忆 TM(SQLite + RapidFuzz)

```sql
CREATE TABLE IF NOT EXISTS tm_entries (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    source_seg    TEXT NOT NULL,
    target_seg    TEXT NOT NULL,
    quality_score REAL DEFAULT 0.0,
    domain        TEXT DEFAULT '',
    user_id       TEXT DEFAULT '',
    timestamp     TEXT,
    UNIQUE(user_id, source_seg)   -- 重复写入走 UPDATE
);
CREATE INDEX IF NOT EXISTS idx_tm_user ON tm_entries(user_id);
```

### 5.3 用户偏好(SQLite)

```sql
CREATE TABLE IF NOT EXISTS user_prefs (
    user_id         TEXT NOT NULL,
    preference_type TEXT NOT NULL,   -- 如 style / tone / direct_or_free / notranslate_terms
    value           TEXT NOT NULL,
    weight          REAL DEFAULT 1.0,
    timestamp       TEXT,
    PRIMARY KEY (user_id, preference_type)
);
```

## 六、检索与写入流程

### 6.1 `search_rag`(译前·术语提取调用)

```
query(候选术语) + domain(策略书领域标签) + user_id
    │
    ├─ ① 缩写/别名精确匹配(rag_aliases.db,SQLite,零 embedding)
    │     命中 → 返回 TermEntry(100% 准确,如 "CPU"→Central Processing Unit;
    │           中文反向 "数字签名"→Digital Signature 同机制命中)
    │     未命中 ↓
    │
    ▼
embedder.embed(query)                    ← 只 embed 一个 query(种子已批量预嵌入,不在运行时重建)
    │
    ▼
ChromaDB query(
    query_embeddings=[emb],
    where={$or:[domain==domain, domain==""], user_id==user_id},   # 领域过滤+无领域兜底
    n_results=top_k)
    │
    ▼
similarity = 1 - distance                 # 余弦距离 → 相似度
    ├─ similarity >= 0.70 → 返回 TermEntry(source="RAG命中")  → 复用历史译法(high)
    └─ 全部 < 0.70        → 返回 []                       → 调用方转 Web 搜索 / LLM 兜底
```

**命中判定是三级查证(RAG → Web → LLM)的关键分界**。`RAG_MIN_SIMILARITY=0.70` 为初始值,D10 用种子数据校准:目标是「该命中的必须命中、容易误配的(如 `pod` vs `Pod` 大小写)不误报」。

### 6.2 `search_tm`(译中·主译译前调用)

```
主译收到翻译任务 → 全部 chunk 源文做 RapidFuzz 全文模糊搜索(对 tm_entries.source_seg)
    └─ fuzz.ratio/WRatio >= 0.85 的句段 → 返回 TMEntry(source_seg, target_seg, similarity)
        → 以 "[TM·87%] 源 → 译" 形式注入主译 prompt 作参考(概念文档 §6.3)
```

### 6.3 写入时机(译后·学习层)

| 写入口 | 触发 | 数据 |
|--------|------|------|
| `write_rag` | 用户确认的术语 + Web 搜索验证过的术语 | TermEntry, confidence=high |
| `write_tm` | 质检评分 ≥ 8.5 的句对,句级对齐后 | TMEntry, quality_score |
| `save_prefs` | 用户每次干预(改术语/调风格/改策略) | {preference_type: value} |

### 6.4 Embedding 性能策略

- **导入时批量预嵌入**:`import_seed.py` 一次性对 200 条种子做 batch encode,写入 ChromaDB 后落盘持久化。
- **运行时只 embed query**:`embedder` 单例持载模型,不重复加载;`search_rag` 每次仅嵌入 1 个候选词。
- **幂等**:collection 已存在且非空时,`import_seed.py` 跳过重建(或按 id upsert)。

## 八、环境与部署(Windows · CPU)

| 依赖 | 说明 |
|------|------|
| `chromadb` | PersistentClient 本地持久化 |
| `sentence-transformers` | 加载 bge-m3(底层需 torch,Windows CPU 版安装即可) |
| `rapidfuzz` | TM 模糊匹配(纯 C 实现,毫秒级) |
| `openpyxl` | 术语表导入器读 xlsx(import_glossary.py) |

**bge-m3 下载(中国网络实测,2026-08)**:HuggingFace 直连/镜像对大文件(2.2GB)均不可靠——新版走 **Xet 传输协议**(CAS 域名墙内不可达)会卡死,且镜像偶发 403(垃圾文件 `.DS_Store`)。**实测可行路径**:
1. `config.py` 已写死 `HF_HUB_DISABLE_XET=1`(禁 Xet 回退经典 HTTP)+ `HF_ENDPOINT=https://hf-mirror.com`;
2. 小文件(权重以外的 config/tokenizer 等)用 ModelScope 拉取:
   `modelscope download --model BAAI/bge-m3 --local_dir models/bge-m3`(加 `--ignore_patterns 'pytorch_model.bin','*.safetensors'`);
3. 大权重文件 `pytorch_model.bin`(~2.2GB)本网络下任何源都会卡死,**手工下载后放入 `models/bge-m3/`**;
4. `embedder.py` 优先加载本地 `models/bge-m3/`(`local_files_only=True`),下载过即离线可用。

**模型体积/耗时**:bge-m3 约 2.2GB,CPU 下单条编码 ~0.1-0.5s。种子 200 条 batch 预嵌入一次约 1-3 分钟(一次性成本);运行期仅 embed query,延迟可控。若现场设备过弱,降级 `bge-base-zh-v1.5`(~400MB)仅改 `config.py` 一处(已在决策中备案)。

## 十一、风险与降级

### 12.2 文件格式与内容契约

| 项 | 约定 |
|----|------|
| 格式 | **CSV(UTF-8)** 首选;xlsx 次选(需 openpyxl) |
| 必填列 | `term`(英文)、`translation`(中文) |
| 建议列 | `domain`(消歧关键,必须用 §12.5 词表) |
| 可选列 | `action`(translate/notranslate)、`confidence`(high/medium/low,默认 high) |

| 编码 | UTF-8 无 BOM;中文列头亦可 |

示例模板:

