## 一、测试范围与目标

验证**译前术语提取**第一层(RAG)的检索质量,回答三个问题:

1. **召回率**:候选术语能否命中正确的库内术语?
2. **排序质量**:正确术语是否排在最前(MRR)?
3. **误报控制**:非 ICT 术语会不会被错误命中(阈值校准的关键)?

## 五、缩写别名解析层(关键优化)

**动机**:官方词库术语都带括注(`Central Processing Unit (CPU)`),源文常见裸缩写 `CPU`,bge-m3 对"缩写↔全称"只给 0.59~0.72 相似度,过不了 0.70。**降阈值会引入负例误报,正确做法是确定性匹配**(概念文档 §4.1 白名单思想)。

**实现**([rag_aliases.py](knowledge_base/rag_aliases.py)):
- 导入时从括注提取别名:`Central Processing Unit (CPU)` → `{CPU, central processing unit}`(键统一小写去空格/标点)
- `search_rag` **先查别名(SQLite,零 embedding)**,命中直接返回(100% 准确),未命中再走语义检索
- 顺带修复潜伏 bug:查 `AI` 原语义 top1 会错返 `Algorithm`,现精确命中 `Artificial Intelligence (AI)`

**效果**:缩写查询 3/8 → 8/8;Recall 75% → 96.9%;别名命中耗时才 ~150ms(比语义快)。

## 六、阈值校准结论:维持 0.70

阈值敏感性(仅语义路径;别名命中的缩写不受阈值影响):

| 阈值 | 语义命中保留 | 负例误判 |
|------|-------------|---------|
| ≥ 0.60 | 97% | **1/3(quantum physics 0.61 误报)** |
| ≥ 0.65 | 94% | 0/3(离误报线仅 0.04) |
| **≥ 0.70(现状)** | 75% | **0/3(离误报线 0.09)** |
| ≥ 0.80 | 38% | 0/3 |

- **降阈值治标不治本**:`quantum physics` 与 ICT 库最近相似度 0.61,阈值压到 0.60 就误报——错误术语被当高置信注入,Web 兜底救不了。
- **别名层已解决语义阈值管不好的缩写类**,0.70 无需改动。
